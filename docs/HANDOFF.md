# Задание для Пёрышка

Довести до работающего интерфейса отправку и просмотр вложений на Android, Web и Windows. Приложение Liaper — для преподавателей и учеников.

## Уже готово

- Сервер и локальная PostgreSQL подключены. Зашифрованные чаты сохраняются до рассылки; архивы уроков синхронизируются в клиентски зашифрованных блобах.
- Файловая нода `liaper-files` на 4201, управляющий сервер на 4000. Серверный протокол: [FILE_STORAGE.md](FILE_STORAGE.md).
- На аккаунт 5 ГиБ, на вложение 128 МиБ, хранение один календарный месяц после загрузки; немедленный запрет скачивания при истечении срока и автоматическая очистка. Учёт объёма и активных загрузок защищён от параллельных запросов.
- Счётчик объёма: Web/Windows «Настройки → Хранилище», Android «Профиль → Хранилище».
- Контакты: только преподаватель приглашает ученика, до 10 подтверждённых учеников на преподавателя. Лимит при принятии заявки атомарно проверяется PostgreSQL; ученик принимает/отклоняет приглашение.
- UX обновлён; на Android своё видео перетаскивается. Debug APK установлен обновлением на подключённый телефон; сервер, файловая нода и Windows-клиент запущены.

## Что сделать

1. Прочитать [UX_UI_AUDIT.md](UX_UI_AUDIT.md), особенно оставшиеся P0. Старый ключ чата выводится из публичного room_id, медиа PCM/JPEG передаются как Base64 без настоящего шифрования, SFU принимает неподписанный вход. Исправить совместимый обмен/хранение ключей прежде, чем передавать файловые ключи через чат. Не объявлять текущие звонки полноценными E2EE.
2. Подключить выбор и отправку PDF, Word и изображений на всех клиентах. Клиент генерирует случайный файловый ключ и nonce, шифрует локально, резервирует квоту, загружает блоб, отправляет описание вложения внутри зашифрованного сообщения. Сервер не получает ключи, исходное имя и MIME в открытом виде.
3. Добавить запись, предпросмотр, отмену, отправку и воспроизведение голосовых сообщений и видеокружков. Запрашивать микрофон/камеру по действию пользователя; корректно освобождать ресурсы. Согласовать форматы воспроизведения Android ↔ Web ↔ Windows.
4. Сделать карточки вложений, прогресс, ошибки, повтор отправки, безопасное локальное открытие/сохранение после расшифровки. При HTTP 410 показывать «Срок хранения истёк», сохраняя сообщение. Обрабатывать 5 ГиБ, 128 МиБ, потерю сети и отмену; обновлять счётчик места.
5. Сохранить правила ролей и лимит 10 учеников. Не удалять существующие данные и не пересоздавать аккаунты/БД при обновлении APK. Секреты находятся в игнорируемой `.env`, в коммит не входят.
6. Проверить настоящую передачу Android ↔ Web ↔ Windows: PDF/Word, изображение, войс, кружок; доступ постороннему, переподключение, истечение срока и квоты. Собрать, установить обновлением APK, пересобрать и запустить Windows-клиент.

## Проверки и запуск

- `cargo test --workspace` — 10 тестов; для реальной PostgreSQL задаётся `LIAPER_TEST_DATABASE_URL` на отдельную `liaper_test`.
- `node tests/file-storage.integration.mjs` — две реальные ноды в изоляции с тестовой БД; шифрование, загрузка, автоматический учёт, доступ контакта и запрет постороннему.
- `node --test clients/web-desktop/tests/lessonArchive.test.mjs` — 4 теста общего формата архивов и конфликтной синхронизации.
- Android: `flutter analyze`, `flutter test` — 9 тестов, `flutter build apk --debug`.
- Web/Windows: `npm.cmd run build`, `npm.cmd run tauri:build -- --debug --no-bundle` в `clients/web-desktop`.
- `start-cluster.ps1` — повторный запуск локальной PostgreSQL, серверов и клиентов. Для пересборки сначала остановить соответствующие EXE: Windows блокирует замену запущенного файла.

Дополнение: после финального изменения серверных проверок приглашений прошли Rust-тесты и сквозной файловый тест. Временная папка UI-стенда осталась в системном Temp, поскольку автоматическая проверка заблокировала её очистку; тестовые аккаунты из `liaper_test` удалены, сам стенд остановлен.
